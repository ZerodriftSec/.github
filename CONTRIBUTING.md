# Contributing

Contributions should improve security, correctness, reproducibility, or documentation clarity.

## Expectations

- Keep changes narrowly scoped.
- Add tests or fixtures when behavior changes.
- Run the repository's documented checks before opening a pull request.
- Do not include secrets, client-confidential material, or unpublished vulnerability details.
- Prefer clear names and explicit assumptions over clever abstractions.

## Repository Status

Each repository README should state one of:

- Production
- Experimental
- Research
- Fixture
- Internal
- Archived

If a repository is experimental or fixture-only, do not present it as production-ready.

## Pull Requests

Use the PR checklist. If a check does not apply, mark it as not applicable and explain briefly.
